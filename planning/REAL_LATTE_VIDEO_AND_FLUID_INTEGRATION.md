# Real recorded Latte Art -> RM65 FK -> virtual FR5 RGB-D -> illustrative fluid

**Technical status, 2026-10-23.** This experimental branch is an extension
of draft PR #17. The shared video is an honestly labeled visualization.
None of the virtual results is a real robot or successful physical latte art.

## Confirmed end-to-end test

GitHub Action: `.github/workflows/latte-real-video.yml`.

1. Download ONE real public episode of `ridxm/latte-pour-demos` via the
   minimal PyArrow importer (400 14D records at 20 Hz).
2. Choose 8–12 seconds of the recorded right-arm motion, then use an
   OFFICIAL but unverified-for-this-hardware `RealManRobot/rm_models`
   RM65-B URDF and an **unmeasured identity flange-to-pitcher transform**
   to compute 79 relative FK poses. There is **41.27 mm** nominal
   relative flange excursion. This is NOT a measured actual spout path.
3. Rigidly align relative poses to a reachable virtual FAIRINO FR5 start,
   solve its kinematic IK with collision preflight, re-render all three
   virtual RGB-D AprilTag cameras, then estimate the pitcher pose
   independently from the rendered images (Pupil AprilTags).
4. Repeat with the camera-tracked poses as the target and a
   **kinematically articulated FR5 in MuJoCo**, rendering the source
   capture and virtual replay side-by-side. This is NOT actual FAIRINO
   spline/firmware execution.
5. A separate CPU `latte_fluid_proxy.py` adds nominal milk color to a
   circular coffee surface via a semi-Lagrangian 2D advection-diffusion
   field. **It is NOT FluidLab, does not model coffee or frothed milk
   material parameters, and its output is NOT a predicted heart.**

### Results obtained (simulated, not real)

- 13/13 camera records valid; each >=2 views.
- All 8/8 fixed reference station tags detected with the LEGACY
  large tags, not the compact AprilTags.
- Max pitcher-body camera reconstruction error vs held-out virtual
  source: **0.5612 mm** (above nominal 0.5 mm goal).
- 13/13 robot replay poses generated by numeric IK and kinematically
  rendered in MuJoCo. Near-zero internal IK-vs-requested-pose numbers
  are expected **by construction**, and do NOT measure servo accuracy,
  grip slip, force/torque, controller smoothing or real spout error.
- Flow proxy is qualitative visual output only: source video does not
  contain milk flow sensor data or a calibrated spout/cup transform.

## Reproduce on Linux or Colab with CPU/MuJoCo OSMesa

```bash
export MUJOCO_GL=osmesa PYOPENGL_PLATFORM=osmesa
python -m pip install -r requirements.txt
python -m pip install 'huggingface_hub>=0.27,<2' 'pyarrow>=16,<23'

python -m robobarista.real_latte_dataset --parquet-only \
  --episode 0 --output runs/real_video_source

git clone --depth 1 --filter=blob:none --sparse \
  https://github.com/RealManRobot/rm_models.git /tmp/rm_models
git -C /tmp/rm_models sparse-checkout set RM65

python -m robobarista.realman_fk_bridge \
  --input-joints runs/real_video_source/recorded_realman_joints.json \
  --urdf /tmp/rm_models/RM65/urdf/RM65-B/urdf/RM65-B.urdf \
  --flange link_6 --joint-names joint_1 joint_2 joint_3 joint_4 joint_5 joint_6 \
  --joint-unit rad --arm right --start-s 8 --end-s 12 \
  --assume-identity-tool --output runs/real_video_fk

python -m robobarista.camera_joint_replay \
  --marker-profile legacy --frames 13 --fps 3 \
  --width 960 --height 720 --seed 14 \
  --external-pitcher-trajectory runs/real_video_fk/source_pitcher_6d_URDF_FK.json \
  --output runs/real_video_fr5_replay

# Artifact: runs/real_video_fr5_replay/demo_and_replay.mp4
python -m robobarista.latte_fluid_proxy \
  --source runs/real_video_fk/source_pitcher_6d_URDF_FK.json \
  --output runs/real_video_fluid/illustrative_2d_milk.mp4
```

All data stays out of Git history and is downloaded for the particular
user-run experiment. The public source dataset currently has no verified
license metadata; verify usage and redistribution permissions.

## Why FluidLab is *not* falsely claimed

FluidLab's own `LatteArt-v0` environment provides a physically inspired
multi-material differentiable simulator, but its documented GL renderer
requires an old CUDA 9.2 compiler and its default demo generates a
hard-coded sinewave. It is NOT a drop-in importer for the Realman
two-arm 14D recording. To use it meaningfully we still need:

- match its cup/agent/pitcher shape, scale and action-space units to a
  calibrated real pitcher and cup;
- expose/transfer cup surface forces, spout height, tilt and actual
  milk mass flow;
- replay the imported source action path in the FluidLab simulator with
  synchronized timing and verify material-parameter sensitivity;
- compare simulated crema pattern to real pours;
- establish a compatible working CUDA/Taichi environment and license.

Until these steps are completed, `latte_fluid_proxy.py` is the
only correctly identified fluid-style preview. Its flow magnitude
and mapping from source XY to cup are explicitly arbitrary.
